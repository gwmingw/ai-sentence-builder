# AI Sentence Builder Booth Demo

초등학생에게 LLM의 “확률적 생성” 원리를 쉽고 재미있게 보여주기 위한 웹 기반 문장 이어가기 부스 데모입니다.

학생이 시작 문장을 고르면 AI가 다음에 이어질 만한 표현 후보를 여러 개 제안합니다. 학생은 후보 중 하나를 고르고, 선택된 표현이 문장에 붙은 뒤 다시 새로운 후보가 만들어집니다. 이 과정을 5단계 반복하면 하나의 짧은 이야기가 완성됩니다.

이 프로젝트는 엄밀한 next-token logits 시각화 도구가 아니라, 부스 운영 안정성과 초등학생의 이해도를 우선한 “샘플링 기반 후보 체험”입니다. UI에는 AI 점수를 보여주지만, 이 값은 실제 모델 내부 확률이 아니라 Solar 모델이 생성한 상대 점수입니다.

## 현재 구현 상태

- Flask 기반 웹앱 구현 완료
- Upstage Solar API 연동
- 기본 모델: `solar-mini`
- 기본 후보 수: 6개
- 기본 진행 단계: 5단계
- DB 없이 브라우저 메모리에서 각 사용자 상태 관리
- 여러 사용자가 동시에 접속해도 각자 독립적으로 체험 가능
- API 실패 또는 타임아웃 시 로컬 fallback 후보 표시
- 후보 요청 결과를 짧게 캐싱해 반복 호출 비용과 지연 감소
- Vercel 배포용 `vercel.json` 포함
- 기존 로컬 LLM/Matplotlib MVP 파일 `sentence_builder.py`는 참고용으로 유지

## 체험 흐름

1. 학생이 시작 문장을 입력하거나 예시 문장을 선택합니다.
2. AI가 현재 문장 뒤에 자연스럽게 붙는 다음 말 후보 6개를 만듭니다.
3. 각 후보에는 AI 점수, 분위기 태그, 짧은 이유가 함께 표시됩니다.
4. 학생이 마음에 드는 후보를 고르면 문장이 이어집니다.
5. 다시 추천, 되돌리기, AI가 하나 골라줘, 처음부터 기능을 사용할 수 있습니다.
6. 5단계가 끝나면 후보/조작 영역은 사라지고 완성된 이야기가 결과 화면에 표시됩니다.

## 주요 UI 특징

- 첫 화면은 설명용 랜딩 페이지가 아니라 바로 체험을 시작하는 화면입니다.
- 체험 시작 후 시작 문장 입력 영역은 숨겨져 화면 집중도를 높입니다.
- 현재까지 만든 문장과 AI 후보 카드가 동시에 보이도록 자동 스크롤합니다.
- 모바일에서는 조작 버튼을 하단 고정 바 형태로 유지합니다.
- 데스크톱 후보 카드는 3 x 2 그리드입니다.
- 모바일 후보 카드는 1열 6개입니다.
- AI 점수 바는 후보별 상대 점수가 잘 보이도록 색상 막대로 표시합니다.
- 문장 진행도 바는 보조 정보이므로 눈에 덜 띄는 색으로 표시합니다.
- 완성 화면은 단계별 문장 조각을 줄바꿈과 애니메이션으로 보여줍니다.
- 전체 폰트는 웹폰트 대신 안정적인 기본 한글 폰트 스택을 사용합니다.

## 기술 구조

```text
브라우저
  -> Flask /api/candidates
    -> Upstage Solar API
      -> 후보 JSON 생성
  <- 후보 목록 반환
```

서버는 사용자별 세션을 저장하지 않습니다. 각 사용자의 현재 문장, 선택 기록, 진행 단계, 온도값은 브라우저 메모리에만 있습니다. 따라서 DB 없이도 여러 부스 방문자가 동시에 독립적으로 사용할 수 있습니다.

## 파일 구조

```text
sentence_builder/
  app.py                  # Flask 앱, API 라우트, Solar 호출, fallback 처리
  requirements.txt        # Python 의존성
  vercel.json             # Vercel 배포 설정
  README.md               # 프로젝트 개요와 실행 방법
  DESIGN.md               # UI/디자인 가이드
  .env.example            # 환경변수 예시
  sentence_builder.py     # 기존 로컬 LLM MVP 참고 파일
  templates/
    index.html            # 메인 화면 템플릿
  public/
    static/
      app.js              # 브라우저 상태 관리와 UI 동작
      styles.css          # 화면 디자인
```

## 환경변수

`.env` 파일을 만들고 다음 값을 설정합니다.

```env
UPSTAGE_API_KEY=your_upstage_api_key_here
UPSTAGE_MODEL=solar-mini
DEFAULT_TEMPERATURE=0.8
MAX_CANDIDATES=6
MAX_STEPS=5
CACHE_TTL_SECONDS=90
```

선택적으로 사용할 수 있는 값:

```env
MAX_PROMPT_CHARS=180
```

## 로컬 실행

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python app.py
```

실행 후 브라우저에서 접속합니다.

```text
http://127.0.0.1:5000/
```

서버 상태 확인:

```text
http://127.0.0.1:5000/health
```

## API

### `GET /`

체험 화면을 렌더링합니다.

### `GET /health`

서버 상태와 현재 모델명을 반환합니다.

예시:

```json
{
  "ok": true,
  "model": "solar-mini"
}
```

### `POST /api/candidates`

현재 문장과 설정값을 받아 다음 말 후보를 반환합니다.

요청 예시:

```json
{
  "text": "오늘 학교에 갔는데",
  "temperature": 0.8,
  "count": 6,
  "step": 1
}
```

응답 예시:

```json
{
  "ok": true,
  "source": "solar",
  "candidates": [
    {
      "text": "친구들이 활짝 웃고 있었어요",
      "score": 92,
      "tone": "상상",
      "why": "문장이 자연스럽게 이어져요"
    }
  ]
}
```

`source` 값은 다음 중 하나입니다.

- `solar`: Upstage Solar API에서 생성한 후보
- `cache`: 짧은 시간 안에 같은 요청이 들어와 캐시에서 반환한 후보
- `fallback`: API 실패, 타임아웃, 파싱 실패 시 로컬 후보

## Solar 프롬프트 방향

Solar 모델에는 다음 조건을 강하게 요청합니다.

- 초등학생에게 안전하고 쉬운 표현 사용
- 현재 문장 뒤에 바로 붙는 자연스러운 문장 조각 생성
- 존댓말 또는 동화체 유지
- 후보 문장은 대체로 `-어요`, `-아요` 계열로 마무리
- 현재 문장을 반복하지 않기
- 후보끼리 서로 다른 방향성을 갖기
- JSON 형식으로만 응답하기

후보 점수는 실제 LLM 내부 logits 또는 next-token 확률이 아닙니다. 부스 설명에서는 “AI가 보기에 자연스러워 보이는 정도를 숫자로 표현한 값”으로 안내하는 것이 적절합니다.

## 부스 운영 메모

- 권장 체험 단계: 5단계
- 권장 후보 수: 6개
- 권장 체험 시간: 1명당 약 1~2분
- 모델은 응답 속도 우선으로 `solar-mini` 사용
- API 키는 브라우저에 노출하지 않고 서버 환경변수로만 관리
- DB가 없으므로 체험 기록은 저장되지 않음
- 운영자가 빠르게 회전시킬 수 있도록 `처음부터` 버튼 제공
- 일정 시간 입력이 없으면 자동 초기화되도록 프론트엔드에서 idle reset 처리

## 배포

Vercel 배포를 고려해 `vercel.json`을 포함했습니다.

배포 시 Vercel 프로젝트 환경변수에 최소한 다음 값을 등록해야 합니다.

```env
UPSTAGE_API_KEY=your_upstage_api_key_here
UPSTAGE_MODEL=solar-mini
```

Vercel의 서버리스 환경에서는 장시간 실행 작업이나 로컬 파일 저장에 의존하지 않아야 합니다. 현재 구조는 요청 단위로 후보를 생성하고 상태를 저장하지 않으므로 단기 부스 운영에 적합합니다.

## 검증 체크리스트

- 로컬에서 `/health`가 정상 응답하는가
- `.env`의 `UPSTAGE_API_KEY`를 읽어 Solar API 호출이 되는가
- 후보가 항상 6개 표시되는가
- 후보 문장이 현재 문장 뒤에 자연스럽게 붙는가
- 후보 점수 바가 잘 보이는가
- 모바일에서 제목, 상태 배지, 조작 버튼이 잘리지 않는가
- 체험 시작 후 시작 문장 영역이 숨겨지는가
- 후보 생성 중 화면 전체 blur 없이 후보 영역 안에서만 loading이 표시되는가
- 5단계 완료 후 완성 화면만 보기 좋게 표시되는가
- API 실패 시 fallback 후보가 표시되는가

## 남은 개선 후보

- 부스용 안내 문구를 별도 운영자 모드로 제공
- 후보 문장 품질을 실제 현장 예시 기반으로 더 미세 조정
- Vercel 배포 후 실제 네트워크 환경에서 응답 시간 측정
- QR 접속용 짧은 안내 페이지 또는 운영자용 리셋 버튼 추가 검토
